## 1. サービス概要（※最後に書いてOK）

色の合わせ方が分からず黒い服を選びがちな人が、ベース色に合う3色の組み合わせと面積の目安を見ながら、黒以外の服も購入候補として考えられるサービス。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

服を選ぶときに、黒い服ばかり選びがちになることがきっかけ。

---

### 2-2. なぜそれが「気になった」のか

黒い服の中でも形の違うものを選んでいるが、黒が大部分を占めるため、他の人には変化に気づいてもらえなかったり、いつも同じように見えてしまったりする。
この状況を変えたいと思った。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

服を選ぶときに、黒い服ばかり選びがちになること。

---

### 3-2. 本当に解決したい課題は何か

- 他の色をどう組み合わせればよいか分からず、色選びに自信が持てないため、黒を選んでしまうから。
- 形の違う黒い服を選んでも、黒が大部分を占めてしまうから。
- 黒だと形が違っても他の人には変化に気づいてもらえないから。
- いつも同じように見えてしまったりするから。

→ 本当に解決したい課題：形の違う服を選んでも、色が黒に偏ってしまい他の人にいつも同じように見えてしまうこと。

## 7. このアプリで実現すること

### MVPで作る機能

- トーン別に並べた色見本から、ベース色を選んで検索する。
- 選んだ色を使用した３色のカラーパターン一覧を表示する。
- 配色パターンの3色をbase・sub・accentとして面積量を視覚的に表示する。

### 本リリースで作る機能

- トレンド色の強調表示。
- 色選択画面に追加でファッションのカテゴリーの選択を可能にする。
- 該当のカラーパターンが与える印象・雰囲気のコメントを表示する。色相・トーンの組み合わせ、面積比率に加え、ファッションカテゴリーの特徴も踏まえて、どのような服装の雰囲気を目指せるかを説明する。
- 光沢や表面の質感を指定して配色を検索する（候補）。
- お気に入りの色を登録する。
- 持っている服の色を登録する。
- 色パターンに対して自身で考えたコーデ写真を自身のみ閲覧できるように登録できる機能（候補）。
- ユーザーがカラーパターンを登録して公開できたり、公開したカラーパターンに対して他のユーザーがスターを付けられるようにすることで、無難な色だったりトレンドの把握ができる機能（候補）。
- ユーザーが配色パターンを登録したときに、GPT APIでコメントを生成する（候補）。

## 8. このアプリの懸念点とその対策


### 懸念点①

- 何が問題になりそうか：表示された色が、実際に着たい服の組み合わせにならない可能性がある。
- なぜそう思うか：色見本だけでは、服の形や素材を含めた見た目を確認できないため。
- そのために考えている対策：MVPでは配色を色選びの目安として提示し、服の形や素材を含めた見た目は実物で確認してもらう。本リリースでは、目指す服装の系統から配色を探せるように、ファッションのカテゴリーによる検索を追加する予定。

### 懸念点②
- 何が問題になりそうか：配色と素材感の組み合わせなどのデータ準備の工数。
- なぜそう思うか：色に関する参考文献を用意するか、ファッションの基礎知識が必要な可能性があるため。
- そのために考えている対策：色に関する参考文献の使用、AIでの基礎データの生成（メンズ、レディース各パターン生成済み）。
  AIで生成済みの配色案について、開発者が参考文献をもとに色相・トーンの関係、各色の役割、面積比率を確認する。比率を反映した配色サンプルでも見え方を確認し、初期の登録件数を絞ることで準備の負担を抑える。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：React, Rails。
- DB：MySQL。MVPから配色などを保存・検索するために使う。
- デプロイ先：Railway, AWS Lightsail, AWSのEC2＋RDS（MySQL）
- 使用予定ライブラリ：
    React Router
    mysql2
    GPT API用にはOpenAI公式のRuby gem `openai`を使う。MVP後の候補。

---

### 10-2. 技術選定の比較検討

Reactは、選択した色に応じて配色を切り替え、3色の組み合わせと面積バランスを視覚的に確認できる画面を作るために使う。画面遷移にもアニメーションを取り入れたいため。
Railsは、検索条件を受け取り、登録済みの配色データを取得する処理に使うため。
MySQLは配色などの保存・検索に使うため。
デプロイ先は検討中。
ライブラリも現在は検討中。

### 10-3.キャッチアップ不足の懸念
Reactの基礎は理解できている部分が多いと感じている。一方、Ruby on Railsは基礎が十分に固まっておらず、Reactより理解に難しさを感じる部分が多いと感じています。そのため、Ruby on Railsを使った実装全般に不安がある状態です。
